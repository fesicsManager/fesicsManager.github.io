중2 정보 · 웹툰 8화 「버그는 컴퓨터 잘못이 아니다」

디버깅 — 버그는 사람이 적은 대로 정확히 실행된 결과

1~n 합 프로그램의 네 버전(정상·초기화가 반복문 안·범위 모자람·부등호 반대)에 n = 1, 2, 5를 넣어 출력과 기대값 n(n+1)/2를 비교했습니다. n = 5 정답 15에 대해 초기화 안은 5, 범위 모자람은 10, 부등호 반대는 0이었고, n = 1에서는 초기화 안 버전이 우연히 1로 맞아 입력을 여러 개 써야 했습니다. 오류의 종류와 테스트를 정리합니다.

프로그램이 이상한 답을 내면 컴퓨터가 틀린 게 아니라 적힌 대로 정확히 한 것입니다. 문법 오류는 실행이 안 되고, 실행 오류는 돌다가 멈추며, 논리 오류는 잘 돌지만 답이 틀립니다. 답을 아는 작은 입력(n = 1, 2, 5)과 경계값(빈 값·음수·큰 수)으로 테스트하고, 중간값을 출력해 어디서 틀어졌는지 찾는 것이 디버깅입니다.

개념 정리

1. 버그는 사람이 적은 대로 정확히 실행된 결과

프로그램이 이상한 답을 내면 컴퓨터가 틀린 게 아니라 적힌 대로 한 거예요. 문법 오류는 실행이 안 되니 금방 알지만, 논리 오류는 실행되면서 틀린 답을 내요. 합계 = 0이 반복문 안에 들어가면 매번 0으로 초기화되어 마지막 값만 남아요. range(n)은 n−1까지라 마지막 수가 빠져요. 버그를 찾는 방법은 테스트: 답을 아는 작은 입력(n=1, 2, 5)을 넣고 출력과 비교해요. 어떤 입력에서 틀리는지가 버그의 위치를 알려 줘요.

계산해 보기

  • n=5 정답 15. "초기화가 안에" → 5. "범위 모자람" → 10. "부등호 반대" → 0.
  • n=1: 정답 1. "범위 모자람" → 0. "초기화 안에" → 1(우연히 맞음!). 그래서 입력을 여러 개 써야 해요.

2. 실험 모형과 실제의 차이

· 실제 버그는 특정 입력(빈 값, 음수, 아주 큰 수)에서만 나타나기도 해요. 경계값을 시험하는 습관이 중요해요.

· 짝의 프로그램에 논리 오류를 일부러 하나 심고 교환해서, 테스트 입력만으로 오류 줄을 찾아 보세요. 찾는 데 쓴 입력을 기록하세요.

3. 생활 속에서 · 이어지는 개념

  • 앱 업데이트의 "버그 수정"은 누군가 테스트로 찾아낸 논리 오류예요.
  • 디버깅은 실력이 없어서 하는 게 아니라, 모든 프로그래머가 매일 하는 일이에요.
각 버전을 실제로 실행: 정상 합 = Σ1..n, 초기화 안에 = n, 범위 모자람 = Σ1..n−1, 부등호 반대 = 0. 기대값 = n(n+1)/2

예제

n = 4에서 출력이 6이면 어떤 버그인가?

기대값 10인데 1~3의 합 6 → 범위 모자람(range(n)은 n−1까지).

평균 함수에 빈 목록을 넣으면 생기는 오류의 종류는?

0으로 나누기 → 실행 오류. 경계값 테스트로 미리 잡는다.
