고등 정보 ① · 웹툰 7화 「두 배 커지면 네 배 느리다」

시간 복잡도 — 가장 큰 항만 남긴다

입력 크기 n을 바꾸며 log₂n·n·n log n·n²·2ⁿ의 연산 횟수와 초당 10⁹번 컴퓨터의 예상 시간을 기록하고, 로그–로그 그래프에서 기울기를 비교했습니다. n = 100 000에서 n²은 10초, n log n은 0.002초였고 2ⁿ은 n = 60에서 36년이었으며, 로그–로그 그래프에서 O(n)은 기울기 1, O(n²)은 기울기 2인 직선이었습니다. 빅오 표기와 효율의 원리를 정리합니다.

이중 반복문은 n × n번 실행되어 입력이 2배면 시간이 4배입니다. 효율은 초 단위 시간이 아니라 n이 커질 때 연산이 어떻게 늘어나는가로 비교하고, 빅오 표기는 가장 빨리 자라는 항만 남깁니다 — 겹치면 곱하고, 나란히 있으면 더하고, 가장 큰 항만 남긴다.

개념 정리

1. 가장 큰 항만 남긴다

이중 반복문은 바깥 n번 × 안쪽 n번 = n²번 실행돼요. n = 4면 16번, n = 100이면 10,000번 — 입력이 2배가 되면 시간은 4배예요. 알고리즘의 효율은 이렇게 "n이 커질 때 연산 횟수가 어떤 식으로 늘어나는가"로 비교하고, 빅오 표기 O(n²)처럼 가장 빨리 자라는 항만 남겨 적어요. 겹치면 곱하고, 나란히 있으면 더하고, 가장 큰 항만 남긴다 — 이것이 빅오의 핵심이에요.

계산해 보기 (초당 10⁹번 컴퓨터)

  • n = 100,000: log₂n ≈ 17번, n = 10⁵번(0.0001초), n log n ≈ 1.7 × 10⁶(0.002초), n² = 10¹⁰(10초), 2ⁿ은 계산 불가.
  • 2ⁿ은 n = 40에서 10¹²(17분), n = 60에서 10¹⁸(36년), n = 100에서 우주 나이의 10⁶배.
  • 같은 문제라도 중복 찾기를 이중 반복문(n²) 대신 집합(set, n)으로 풀면 n = 10⁵에서 10만 배 빨라요.

2. 실험 모형과 실제의 차이

· 빅오는 상수를 무시해요. n이 작을 때는 O(n²) 알고리즘이 O(n log n)보다 빠를 수도 있어요.

· 문제 유형별 대표 효율 — 탐색 log n, 정렬 n log n, 모든 쌍 비교 n², 모든 조합 2ⁿ, 모든 순서 n!.

3. 생활 속에서 · 이어지는 개념

  • 친구 목록 1만 명에서 이름을 찾을 때 처음부터 훑으면(n) 1만 번, 정렬된 목록을 반씩 자르면(log n) 14번.
  • 암호가 안전한 까닭도 2ⁿ이에요. 열쇠가 1비트 늘 때마다 뚫는 시간이 2배가 돼요.

뭉치 · 제로 · 닥터 이안

“A는 0.1초, B는 0.2초! A가 두 배 빠르다! 끝!” “데이터가 몇 개였는데?” “100개: A 10초, B 2초. 1000개: A 1000초, B 20초. 역전됐다. A는 n², B는 n. 초 단위 시간이 아니라 ‘커질 때 어떻게 늘어나는가’가 효율이다.”

예제

3n² + 50n + 1000 연산인 알고리즘의 빅오는? n = 10⁶에서 대략 몇 초(10⁹/s)?

O(n²). 3 × 10¹² ÷ 10⁹ = 약 3000초(50분).

친구 1만 명 목록에서 이름을 찾을 때 처음부터 훑기 vs 정렬 목록 이진 탐색의 비교 횟수는?

훑기 최대 10 000번(O(n)), 이진 탐색 log₂10 000 ≈ 14번(O(log n)).
