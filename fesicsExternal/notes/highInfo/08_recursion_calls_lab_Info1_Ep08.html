재귀 — 큰 문제를 같은 모양의 작은 문제로

하노이 탑과 피보나치를 실제 재귀로 실행해 호출(이동) 횟수와 초당 10⁷번 기준 시간을 기록하고, 값을 저장하는 메모이제이션을 켰을 때와 비교했습니다. 하노이 n = 8은 255번, 피보나치 단순 재귀는 n = 35에서 29 860 703번이었지만 저장하면 69번으로 40만 배 줄었습니다. 재귀의 구조와 중복 계산, 분할 정복을 정리합니다.

재귀는 함수가 자기 자신을 더 작은 입력으로 부르는 것이며 반드시 멈추는 조건(원판 1개)이 있어야 합니다. 정의는 세 줄이지만 실행이 빠르다는 보장은 없어서, 같은 값을 수없이 다시 계산하는 피보나치는 저장(메모이제이션)으로 n번이면 끝납니다. 재귀 자체가 느린 게 아니라 중복 계산이 느린 것입니다.

개념 정리

1. 큰 문제를 같은 모양의 작은 문제로

재귀는 함수가 자기 자신을 더 작은 입력으로 부르는 방법이에요. 하노이 탑 n개는 "n−1개를 옮기고, 가장 큰 것을 옮기고, n−1개를 다시 옮기기"라 H(n) = 2H(n−1) + 1, 즉 2ⁿ − 1번이에요(1, 3, 7, 15 … 8개 = 255). 피보나치를 fib(n) = fib(n−1) + fib(n−2)로 그대로 부르면 같은 값을 수없이 다시 계산해 호출 횟수가 1.6ⁿ으로 늘어요(n = 35에서 3천만 번). 이미 구한 값을 저장해 두면(메모이제이션) 호출은 n번이면 끝나요.

계산해 보기

  • 하노이: n = 8 → 255번, n = 20 → 약 100만 번, n = 64 → 1.8 × 10¹⁹번(초당 1개면 5,800억 년).
  • 피보나치 단순 재귀 호출 수 C(n) = C(n−1) + C(n−2) + 1: n = 20 → 21,891, n = 30 → 2,692,537, n = 35 → 29,860,703.
  • 저장하면 n = 35에서 69번. 40만 배 차이.

단순 재귀 호출 저장하면 n = 35 이면 29,860,703번 vs 69번

동그라미 하나가 함수 호출 한 번, 같은 색은 같은 값을 구하는 호출입니다. 단순 재귀에서는 f(3)·f(2) 가 여러 번 다시 계산돼요. '값 저장'을 누르면 이미 구한 값(회색)은 바로 꺼내 쓰므로 호출이 2n − 1 번으로 줄어요.

2. 실험 모형과 실제의 차이

· 재귀가 너무 깊으면 호출 정보를 쌓아 두는 스택이 넘쳐요(파이썬 기본 1,000단계). 반복문이나 저장 방식으로 바꾸는 이유예요.

· 분할 정복 — 반으로 나눠 풀고 합치기(병합 정렬)는 재귀지만 호출 수가 n log n이라 효율적이에요. 재귀 자체가 느린 게 아니라 중복 계산이 느린 거예요.
