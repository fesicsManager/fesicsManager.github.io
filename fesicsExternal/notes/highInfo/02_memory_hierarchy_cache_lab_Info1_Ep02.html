고등 정보 ① · 웹툰 2화 「캐시는 책상, 메모리는 책장, 디스크는 창고」

기억장치 계층 — 가까운 곳에 자주 쓰는 것을 둔다

캐시 4 MB(1 ns)·메모리 16 GB(100 ns)·디스크(100 000 ns) 모형에서 배열 크기와 접근 방식(순서대로·건너뛰기·무작위)을 바꾸며 캐시 적중률과 평균 접근 시간을 기록했습니다. 순서대로 읽기는 적중률 94 %·평균 7 ns였고 무작위는 적중률 0 %·100 ns로 10배 이상 느렸으며, 배열이 메모리보다 커지면 1000배 더 느려졌습니다. 지역성과 가상 메모리의 원리를 정리합니다.

실험에서 얻은 것

실험 데이터 되짚기

실험 안내: 캐시 4 MB(1 ns), 메모리 16 GB(100 ns), 디스크(100 000 ns)로 둡니다. 캐시 줄 하나는 정수 16개입니다.

캐시는 데이터를 줄(64바이트 = 정수 16개) 단위로 가져오므로 순서대로 읽으면 16개 중 15개는 이미 가져와 둔 것입니다(공간 지역성). 무작위로 읽으면 매번 새 줄을 가져와야 하고, 배열이 메모리보다 크면 디스크(가상 메모리)까지 가서 1000배 더 느립니다. 코드 짜는 방식이 하드웨어 속도를 바꿉니다.

개념 정리

1. 가까운 곳에 자주 쓰는 것을 둔다

CPU 바로 옆의 캐시는 빠르지만 작고(수 MB), 메모리는 100배 느리지만 크며(수 GB), 디스크는 그보다 1000배 더 느리지만 아주 커요. 그래서 "자주·곧 다시 쓸 것은 가까이" 두는 계층 구조를 만들어요. 캐시는 데이터를 한 칸씩이 아니라 줄(cache line, 64바이트 = 정수 16개) 단위로 가져오므로, 배열을 순서대로 읽으면 16개 중 15개는 이미 가져와 둔 것(적중)이에요. 무작위로 읽으면 매번 새 줄을 가져와야 해서 느려요. 이것이 공간 지역성이에요.

계산해 보기

  • 순서대로 읽기: 적중률 15/16 ≈ 94 %. 평균 시간 = 0.94 × 1 + 0.06 × 100 ≈ 7 ns.
  • 무작위 읽기(배열이 캐시보다 훨씬 큼): 적중률 ≈ 0 %. 평균 ≈ 100 ns → 순서대로가 10배 이상 빠름.
  • 배열이 메모리보다 커서 디스크(가상 메모리)를 쓰면: 접근 하나에 100,000 ns → 1000배 더 느려요.

2. 실험 모형과 실제의 차이

· 실제 CPU는 L1·L2·L3 캐시 세 단계와 미리 읽기 장치가 있어 순차 접근은 더 빠르고, 무작위 접근도 완전히 0 %는 아니에요.

· 2차원 배열을 행 우선/열 우선으로 더하는 두 코드의 시간 차이가 바로 이 실험이에요. 직접 재 보세요.

3. 생활 속에서 · 이어지는 개념

  • 가상 메모리: 메모리가 부족하면 디스크를 메모리처럼 써요. 탭을 너무 많이 열면 갑자기 느려지는 까닭이에요.
  • 브라우저 캐시, CDN, 게임의 로딩 화면 — 모두 "느린 곳에서 미리 가져와 가까이 두기"예요.
캐시 적중률 h = 순서대로 15/16, 16칸 건너뛰기 0, 무작위 min(1, 캐시 크기 ÷ 배열 크기), 평균 접근 시간 = h × 1 ns + (1 − h) × (배열이 메모리에 들어가면 100 ns, 아니면 일부는 100,000 ns)

예제

적중률 90 %, 캐시 1 ns, 메모리 100 ns일 때 평균 접근 시간은?

0.9 × 1 + 0.1 × 100 = 10.9 ns. 적중률 10 %p 차이가 시간을 크게 바꾼다.

브라우저 탭을 너무 많이 열면 컴퓨터가 갑자기 느려지는 까닭은?

메모리가 넘쳐 운영체제가 안 쓰는 페이지를 디스크로 내보내고(가상 메모리), 다시 필요할 때 1000배 느린 디스크에서 가져오기 때문. ‘메모리 부족’이 ‘느려짐’으로 나타난다.
