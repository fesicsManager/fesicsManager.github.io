클래스와 객체 — 데이터와 동작을 한 덩어리로

캐릭터 수 N·속성 수·동작 수를 바꾸며 변수 따로·속성별 리스트·클래스 세 방식의 코드 줄 수와, 속성 하나를 추가할 때 고쳐야 하는 곳 수를 기록했습니다. 캐릭터 100명·속성 3·동작 2에서 변수 따로는 500줄, 클래스는 약 12줄이었고 속성 추가 시 수정 곳은 100 → 1이었으며, 캐릭터가 2~3명뿐일 때는 클래스가 오히려 길었습니다. 객체 지향의 원리를 정리합니다.

클래스는 ‘캐릭터란 이름·체력·공격력을 가지고 공격·회복을 할 수 있는 것’이라는 설계도이고, 객체는 그 설계도로 찍어 낸 실제 캐릭터입니다. 설계도는 한 번만 쓰고 생성은 세 줄이면 100명이 생기며, 고칠 곳이 한 곳이 됩니다. 프로그래밍의 역사는 고칠 곳을 줄이는 역사입니다 — 함수 → 모듈 → 객체.

개념 정리

1. 데이터와 동작을 한 덩어리로

캐릭터 100명의 이름·체력·공격력을 변수로 따로 만들면 300개의 변수와 300줄이 필요하고, "체력 회복" 동작도 100번 짜야 해요. 클래스는 "캐릭터란 이름·체력·공격력을 가지고, 공격하기·회복하기를 할 수 있는 것"이라는 설계도이고, 객체는 그 설계도로 찍어 낸 실제 캐릭터예요. 설계도는 한 번만 쓰고 for i in range(100): 캐릭터들.append(캐릭터()) 세 줄이면 100명이 생겨요. 상속을 쓰면 '마법사'는 '캐릭터'의 모든 것을 물려받고 '마법'만 추가하면 돼요. 객체는 명사, 메서드는 동사예요.

계산해 보기

  • 변수 따로: 줄 수 = 캐릭터 수 × 속성 수 (+ 동작마다 캐릭터 수만큼). 속성 추가 → 캐릭터 수만큼 고침.
  • 리스트 묶음: 속성별 리스트 + 반복문. 속성 추가 → 리스트 하나 + 그 속성을 쓰는 동작마다 수정.
  • 클래스: 클래스 정의(속성 수 + 동작 수 × 2) + 생성 3줄. 속성 추가 → 클래스 안 한 곳.

2. 실험 모형과 실제의 차이

· 캐릭터가 2~3명뿐이면 클래스가 오히려 길어요. 객체 지향은 프로그램이 커지고 오래 바뀔 때 힘을 발휘해요.

· '도서' 클래스(제목·저자·대출 여부 / 대출하기·반납하기)를 만들고 도서 5권을 객체로 만들어 대출·반납을 실행해 보세요.

3. 생활 속에서 · 이어지는 개념

  • 게임의 몬스터, 쇼핑몰의 상품, 학교의 학생 — 프로그램 속 "물건"은 거의 모두 객체예요.
  • 스마트폰 앱의 버튼·화면도 객체예요. "버튼을 누르면"은 버튼 객체의 메서드예요.
변수 따로 = N × 속성 + N × 동작, 리스트 = 속성 + 동작 × 3 + 2, 클래스 = 속성 + 2 + 동작 × 2 + 3; 속성 추가 수정 곳 = N / 동작 + 1 / 1
뭉치 · 제로 · 닥터 이안

“캐릭터 3명 게임! 변수 30개! 캐릭터 추가하면 변수 10개 더!” “100명이면 변수 1000개?” “캐릭터가 가진 것(속성)과 하는 것(메서드)을 하나로 묶는다. 설계도 하나로 캐릭터 100명을 찍어 낸다. 그게 객체다.”

예제

‘도서’ 클래스의 속성과 메서드를 설계하면?

속성: 제목·저자·대출 여부. 메서드: 대출하기()·반납하기(). 도서 5권 = 객체 5개, 대출 규칙 변경은 클래스 한 곳.

‘마법사’가 ‘캐릭터’를 상속하면 무엇을 물려받고 무엇만 추가하나?

이름·체력·공격력과 공격·회복을 모두 물려받고 ‘마법’만 추가. 공통은 부모에, 차이는 자식에.
