DNS — 이름을 숫자 주소로 바꾼 뒤에야 접속한다

주소창에 누리집 이름을 쳤을 때 처음 방문 · 바로 다시 방문 · 이름 안내가 막힌 컴퓨터 · 숫자 주소 직접 입력 상황과, 가까운 DNS 서버가 이름을 아는지 바꾸며 단계 수·걸린 시간(가상)·결과를 기록했습니다. 처음 방문은 3단계 70 ms, 가까운 서버가 모르면 6단계 160 ms, 다시 방문하면 50 ms였고, 이름 안내가 막히면 서버가 멀쩡해도 접속하지 못했어요. 도메인 이름과 IP 주소, DNS와 기억(캐시)을 정리합니다.

실험에서 얻은 것

실험 데이터 되짚기

실험 안내: 자유 탐구 탭에서 상황(처음 방문 · 바로 다시 방문 · 이름 안내가 막힌 컴퓨터 · 주소창에 숫자 주소 직접 입력)과 가까운 DNS 서버가 이 이름을(알고 있다 · 모른다)을 고르고 실행하면 질문과 답이 오가는 순서가 화살표로 그려지고 단계 수, 걸린 시간(가상), 결과가 표시됩니다. ‘처음 방문’과 ‘바로 다시 방문’의 시간을 비교하고, ‘이름 안내가 막힌 컴퓨터’에서 어떤 오류가 나는지 기록해 보세요. 이름·숫자 주소는 설명용 예시입니다.

표 1. 상황별 이름 안내 과정 (실험 예시, 시간은 단순 모형의 가상 값)
상황가까운 DNS단계시간(가상)결과
처음 방문앎3단계70 ms열림
처음 방문모름6단계160 ms열림
바로 다시 방문—2단계50 ms열림
이름 안내 막힘—1단계—오류 (IP 주소를 찾을 수 없음)
숫자 주소 직접 입력—1단계50 ms열림

브라우저는 이름으로 곧장 접속하지 못하고 먼저 DNS에 IP 주소를 묻고, 숫자를 받은 뒤에야 접속합니다. 가까운 서버가 모르면 윗단계에 차례로 물어 시간이 늘고(70 → 160 ms), 한 번 알아낸 번호는 기억해 두어 다시 방문할 때는 묻는 과정을 건너뜁니다(50 ms). 이름 안내가 막히면 길은 있는데 번호를 몰라 ‘서버의 IP 주소를 찾을 수 없음’ 오류가 나요.

개념 정리

1. 이름을 숫자 주소로 바꾸는 안내 체계

라우터는 숫자 주소(IP 주소)로 길을 찾습니다. 사람이 외우기 쉬운 도메인 이름을 IP 주소로 바꿔 주는 이름 안내 체계가 DNS예요. 스마트폰 연락처가 "엄마"를 전화번호로 바꿔 주는 것과 같습니다.

2. 묻는 순서

  1. 내 기기의 기억(캐시): 최근에 알아낸 번호가 있으면 바로 씁니다.
  2. 가까운 DNS 서버: 보통 통신사나 학교망이 제공해요.
  3. 더 윗단계 서버: 가까운 서버도 모르면 윗단계 서버들에 차례로 물어 알아냅니다. 전 세계 이름을 한 곳이 다 들고 있는 게 아니라 여러 서버가 나눠 맡아요.

3. 이름 안내가 안 되면

서버는 멀쩡해도 "서버의 IP 주소를 찾을 수 없음" 같은 오류가 납니다. 길은 있는데 번호를 모르는 거예요.

4. 실험 모형과 실제의 차이

· 걸린 시간은 기억 0 ms, 가까운 서버 20 ms, 윗단계 한 번 30 ms(3단계), 접속 50 ms로 둔 가상 값입니다. 실제 시간은 망 상태에 따라 크게 달라요.

· 203.0.113.x는 문서·예시용으로 따로 정해 둔 주소 범위입니다.

도메인 이름 → (기억 → 가까운 DNS 서버 → 윗단계 서버) → IP 주소 → 서버에 접속

예제

실험 모형은 기억 0 ms, 가까운 서버 20 ms, 윗단계 한 번 30 ms(3단계), 접속 50 ms로 둔다. 처음 방문에서 가까운 서버가 이름을 모를 때 걸린 시간을 구하시오.

가까운 서버 20 ms + 윗단계 30 ms × 3 + 접속 50 ms = 20 + 90 + 50 = 160 ms입니다. 160 ms

인터넷 연결은 정상인데 누리집 이름으로 들어가면 ‘서버의 IP 주소를 찾을 수 없음’ 오류가 뜬다. 가장 먼저 의심할 곳은?

찾지 못한 것은 서버가 아니라 서버의 번호입니다. 이름을 IP 주소로 바꾸는 이름 안내(DNS) 과정을 먼저 의심해야 하고, 서버 자체는 멀쩡할 수 있어요.
