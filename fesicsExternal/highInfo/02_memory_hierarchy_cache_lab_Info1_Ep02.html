캐시는 책상, 메모리는 책장, 디스크는 창고 — 기억장치 계층

이번에는 같은 배열을 순서대로 읽을 때와 무작위로 읽을 때 캐시 적중률이 어떻게 달라지고, 평균 접근 시간이 몇 배 차이 나는지 잽니다. 메모리가 모자라 디스크까지 내려가면 왜 갑자기 느려지는지도 확인합니다.
※ 접근 시간(캐시 1 ns·메모리 100 ns·디스크 100,000 ns)과 적중률 식은 교육용 어림 모형이에요. 실제 CPU는 캐시가 3단계이고 미리 읽기(프리페치)도 해요.

🔑 핵심 원리 — 가까운 곳에 자주 쓰는 것을 둔다

CPU 바로 옆의 캐시는 빠르지만 작고(수 MB), 메모리는 100배 느리지만 크며(수 GB), 디스크는 그보다 1000배 더 느리지만 아주 커요. 그래서 "자주·곧 다시 쓸 것은 가까이" 두는 계층 구조를 만들어요. 캐시는 데이터를 한 칸씩이 아니라 줄(cache line, 64바이트 = 정수 16개) 단위로 가져오므로, 배열을 순서대로 읽으면 16개 중 15개는 이미 가져와 둔 것(적중)이에요. 무작위로 읽으면 매번 새 줄을 가져와야 해서 느려요. 이것이 공간 지역성이에요.

⚙️ 계산해 보기

  • 순서대로 읽기: 적중률 15/16 ≈ 94 %. 평균 시간 = 0.94 × 1 + 0.06 × 100 ≈ 7 ns.
  • 무작위 읽기(배열이 캐시보다 훨씬 큼): 적중률 ≈ 0 %. 평균 ≈ 100 ns → 순서대로가 10배 이상 빠름.
  • 배열이 메모리보다 커서 디스크(가상 메모리)를 쓰면: 접근 하나에 100,000 ns → 1000배 더 느려요.

🧮 이 실험의 계산 방법

캐시 적중률 h = 순서대로 15/16, 16칸 건너뛰기 0, 무작위 min(1, 캐시 크기 ÷ 배열 크기), 평균 접근 시간 = h × 1 ns + (1 − h) × (배열이 메모리에 들어가면 100 ns, 아니면 일부는 100,000 ns)

📌 실험 모형과 실제의 차이
· 실제 CPU는 L1·L2·L3 캐시 세 단계와 미리 읽기 장치가 있어 순차 접근은 더 빠르고, 무작위 접근도 완전히 0 %는 아니에요.
· 2차원 배열을 행 우선/열 우선으로 더하는 두 코드의 시간 차이가 바로 이 실험이에요. 직접 재 보세요.

🌍 생활 속에서

  • 가상 메모리: 메모리가 부족하면 디스크를 메모리처럼 써요. 탭을 너무 많이 열면 갑자기 느려지는 까닭이에요.
  • 브라우저 캐시, CDN, 게임의 로딩 화면 — 모두 "느린 곳에서 미리 가져와 가까이 두기"예요.

왼쪽부터 캐시(책상) → 메모리(책장) → 디스크(창고)입니다. 초록 화살표는 캐시에서 찾은 접근(적중), 빨간 화살표는 아래 계층까지 내려간 접근(실패)입니다.
