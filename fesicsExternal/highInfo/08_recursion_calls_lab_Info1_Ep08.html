재귀는 자기 자신을 부른다 — 호출 횟수 세기

이번에는 하노이 탑, 피보나치(단순 재귀), 피보나치(계산 결과 저장)에서 n을 키울 때 함수 호출 횟수가 어떻게 늘어나는지 세고, 같은 문제도 결과를 저장하면 왜 수백만 배 빨라지는지 확인합니다.
※ 호출 횟수는 실제로 재귀를 돌려 센 값이고, 시간은 초당 10⁷번 호출 기준 어림값이에요.

📖 정보 원리 — 어떤 원리로 이렇게 될까?

🔑 핵심 원리 — 큰 문제를 같은 모양의 작은 문제로

재귀는 함수가 자기 자신을 더 작은 입력으로 부르는 방법이에요. 하노이 탑 n개는 "n−1개를 옮기고, 가장 큰 것을 옮기고, n−1개를 다시 옮기기"라 H(n) = 2H(n−1) + 1, 즉 2ⁿ − 1번이에요(1, 3, 7, 15 … 8개 = 255). 피보나치를 fib(n) = fib(n−1) + fib(n−2)로 그대로 부르면 같은 값을 수없이 다시 계산해 호출 횟수가 1.6ⁿ으로 늘어요(n = 35에서 3천만 번). 이미 구한 값을 저장해 두면(메모이제이션) 호출 수는 n에 비례(O(n))해 끝나요.

⚙️ 계산해 보기

  • 하노이: n = 8 → 255번, n = 20 → 약 100만 번, n = 64 → 1.8 × 10¹⁹번(초당 1개면 5,800억 년).
  • 피보나치 단순 재귀 호출 수 C(n) = C(n−1) + C(n−2) + 1: n = 20 → 21,891, n = 30 → 2,692,537, n = 35 → 29,860,703.
  • 저장하면 n = 35에서 69번. 40만 배 차이.

🧮 이 실험의 계산 방법

실제로 재귀 함수를 돌려 호출 횟수를 셉니다(n ≤ 30). 시간 ≈ 호출 횟수 ÷ 10⁷/초

📌 실험 모형과 실제의 차이
· 재귀가 너무 깊으면 호출 정보를 쌓아 두는 스택이 넘쳐요(파이썬 기본 1,000단계). 반복문이나 저장 방식으로 바꾸는 이유예요.
· 분할 정복 — 반으로 나눠 풀고 합치기(병합 정렬)는 재귀지만 호출 수가 n log n이라 효율적이에요. 재귀 자체가 느린 게 아니라 중복 계산이 느린 거예요.
