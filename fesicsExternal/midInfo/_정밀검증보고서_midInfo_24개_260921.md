## 2. 공통 기술 검증

### 정상 확인

- 24개 전부 `<!doctype html>`, UTF-8, viewport 선언 확인
- 인라인 JavaScript 전체 구문 정상
- 중복 `id` 없음
- 외부 파일 호출 없이 단독 실행 가능한 구조
- 실행 버튼, 기록 자동 추가, 기록 삭제, 자유 탐구/데이터 검증 전환 로직 존재
- `aria-selected`, `aria-controls`, `aria-pressed`, 캔버스 `aria-label` 일부 적용
- 640 px 이하에서 실험 영역이 1열로 전환
- 키보드 초점 표시와 모션 감소 설정 포함

### 공통 보완 사항

1. **탭 위젯 키보드 조작 미구현 (B)**  
   모든 파일에서 `role="tab"`은 있으나 roving `tabindex`와 방향키(←/→, Home/End) 처리가 없습니다. 선택되지 않은 탭도 탭 순서에 남고 WAI-ARIA 탭 패턴을 충족하지 못합니다.

2. **동적 range 입력의 접근 가능한 이름 미흡 (B)**  
   슬라이더는 `id`만 생성되고 `<label for>` 또는 `aria-label`/`aria-labelledby`가 없습니다. 화면의 시각적 문구와 폼 컨트롤이 프로그램적으로 연결되도록 수정해야 합니다.

3. **캔버스 대체 콘텐츠 부재 (B)**  
   `aria-label`은 있으나 모든 캔버스 내부 fallback text가 비어 있습니다. 핵심 결과가 캔버스에만 그려질 때 낭독기 사용자는 그래프·도식의 변화를 알기 어렵습니다. 결과 요약을 `aria-live="polite"` 텍스트로 동기화하거나 캔버스 아래 표로 제공해야 합니다.

4. **실행 중 상태 알림 부족 (C)**  
   계산 결과 영역과 기록 변화에 `aria-live`가 없어 실행 완료와 결과 변경이 낭독기에 자동 공지되지 않을 수 있습니다.

5. **정적 버튼의 `type="button"` 누락 (C)**  
   현재 `<form>` 밖이어서 즉시 문제는 없지만, 추후 폼 안으로 이동하면 의도치 않은 submit이 발생할 수 있습니다.
