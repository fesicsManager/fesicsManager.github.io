# midEnv 환경 실험 파일 정밀 검증 보고서

- 검증일: 2026-09-21
- 대상: `fesicsExternal/midEnv`
- 파일: HTML 8개 + `units.json` 1개
- 검증 범위: HTML/JavaScript 구문, DOM 참조와 중복 ID, 외부 의존성, 입력 범위와 계산식, 단위, 결과 기록·검증 탭 흐름, 과학적 타당성, 교육 표현, 반응형·접근성 코드

## 종합 판정

**조건부 통과 — 즉시 수정 2건, 중요 수정 4건, 보완 권장 8건**

8개 HTML 모두 JavaScript 구문 오류가 없고, 중복 ID와 누락된 정적 자원도 없습니다. 모든 파일은 외부 CDN 없이 단일 HTML로 동작하도록 구성되어 있습니다. 공통 UI에는 모바일 viewport, 반응형 CSS, 캔버스 고해상도 처리, 자동 기록, 4회 이상 기록 뒤 검증 탭 분석, 결과 초기화가 포함되어 있습니다.

다만 06화의 비교 실험 설계와 08화의 10년 사용 계산에는 결과 해석을 왜곡할 수 있는 핵심 문제가 있습니다. 01·04·05·07화는 모형의 가정 또는 용어를 명확히 표시해야 합니다.

> 실행 환경 제한: 브라우저 엔진 다운로드가 네트워크 오류로 완료되지 않아 실제 Chromium 클릭·렌더링 검사는 수행하지 못했습니다. 대신 8개 전체 스크립트 구문 검사, DOM 정합성 검사, 계산식·입력 범위·상태 전환 코드 추적을 완료했습니다.

## 파일별 상세 결과

### 01. 병 속 온실효과

- 기능/코드: 구문·DOM·기록 흐름 정상.
- 계산: 지수 접근식은 일관되며 시간·밝기에 따라 평형값으로 수렴합니다.
- 중요 보완: `공기 k=8`, `CO₂ 채움 k=12`, `CO₂ 2배 k=14`는 실측 상수가 아닌 임의 모형값입니다. 화면에 “교육용 가상 계수”라고 표시해야 합니다.
- 표현: “CO₂ 2배”가 공기 중 농도 2배인지, CO₂로 채운 병의 2배인지 불명확합니다. `대기 CO₂ 농도 2배 모형`처럼 정의가 필요합니다.
- 판정: **B — 과학적 한계 설명 후 사용 권장**.

### 02. 추운 겨울과 장기 추세

- 기능/코드: 구문·계산·회귀·기록 흐름 정상.
- 장점: 연간 변동과 장기 추세를 분리하고 30·60·100년 기간 비교가 가능합니다.
- 보완: “서울 1월 평균 기온 모형 자료”가 실제 관측자료가 아닌 생성자료임을 결과 화면에도 반복 표시해야 합니다.
- 보완: 10년 이동평균이 현재 코드상 중앙 부근 10개 자료를 쓰고 양 끝에서는 창 길이가 짧아집니다. 일반적인 후행 10년 평균과 다르므로 `중심 이동평균(끝 구간 축소)`로 명시하거나 계산법을 통일하세요.
- 판정: **통과(표시 보완 권장)**.

### 03. 탄소발자국 원그래프

- 기능/코드: 합계·비율·상위 항목·10% 감축 계산이 일관됩니다.
- 단위: 4인 가족 1년, kg CO₂라는 기준이 표시되어 있습니다.
- 보완: 난방·식품·소비재 값이 출처 없는 대표값입니다. “실제 진단값이 아닌 비교용 가정”과 기준 연도/지역을 표시하세요.
- 보완: 자동차 `0.2 kg/km`는 차량·연료에 따라 달라지는 값이므로 고정값의 출처 또는 범위를 제시하세요.
- 판정: **통과(자료 출처 보완 권장)**.

### 04. LED 교체 본전 계산

- 기능/코드: 전력량 `W×개수×시간×365/1000`, 요금, 배출량 계산은 일관됩니다.
- 중요 보완: 동일 밝기를 6 W의 ‘빛’으로 고정한 뒤 나머지를 모두 열로 표시하는 그림은 실제 광효율을 정확히 나타내지 않습니다. 시각화는 `입력 전력 비교` 중심으로 바꾸는 편이 안전합니다.
- 중요 보완: 본전 계산은 총 구매비를 절감액으로 나눈 단순 모형입니다. 교체 시점과 수명에 따른 재구매 비용을 반영하지 않습니다.
- 표현 오류: 수명 결과의 `백열등 기준 n배`는 설정값을 그대로 사용하므로 “가정 수명”이라고 써야 합니다.
- 판정: **B — 단순 모형 표기 필요**.

### 05. 태양광과 저장

- 기능/코드: 시간별 발전·수요·충전·방전·백업·잉여 계산은 내부적으로 일관됩니다.
- 중요 보완: 하루 시작 SOC가 항상 0입니다. 배터리 용량이 커도 전날 저장분을 쓰지 못하므로 하루 경계에 따라 자급률이 달라집니다.
- 권장 수정: 여러 날 반복 후 주기 정상상태에 도달한 값으로 평가하거나, 시작 SOC 선택/표시를 추가하세요.
- 보완: 충·방전 효율 100%, 용량 손실 없음, 출력 제한 없음이라는 이상 조건을 명시하세요.
- 판정: **B — 경계조건과 가정 표시 필요**.

### 06. 작물 다양성과 안정성

- 기능/코드: 구문과 결과 기록은 정상.
- 즉시 수정: 작물 수에 따라 난수 seed가 달라져 공정한 비교가 아닙니다.
- 과학 표현: 콩을 벌 의존 작물로 단순 분류한 부분은 지나친 일반화입니다. 콩은 자가수분 비중이 높고 곤충이 수량을 높일 수 있으므로 “벌 의존”보다는 “곤충 도움” 등 단계형 설정이 적절합니다.
- 모형 한계: 작물별 병 발생이 서로 독립이고 모든 작물 생산성이 동일하게 `100/n`입니다. 공통 병원체·기상 재해·작물별 생산성 차이를 제외한 단순 보험 모형이라고 표시하세요.
- 판정: **A/B — 비교 실험 로직 수정 후 사용**.

### 07. 미세먼지 크기와 마스크

- 기능/코드: 농도·여과·통과율 곱셈과 UI 흐름은 일관됩니다.
- 중요 수정: 입자별 농도 등급 기준 분리 필요.
- 과학 표현: `PM1 혈액까지 80% 도달`, `PM2.5 폐포 60% 도달`은 일반화된 고정 비율로 보기 어렵습니다. 입자 침착은 크기 외에도 호흡 방식과 개인차에 좌우됩니다. 정확한 비율처럼 제시하지 말고 교육용 상대지수로 바꾸세요.
- 마스크: KF80/KF94 수치를 실제 착용자의 총 흡입 감소율로 그대로 사용합니다. 얼굴 밀착도와 누설을 제외한 `필터 성능 가정`임을 표시하세요.
- 판정: **B — 기준·용어 수정 필요**.

### 08. 스마트폰 순환 사용

- 기능/코드: UI 흐름은 정상이나 계산과 타임라인이 불일치합니다.
- 즉시 수정: 배터리 횟수, 두 번째 이후 기기의 실제 사용 기간, 수리 횟수, 폐기물 집계를 시간축 기반으로 재작성해야 합니다.
- 표현: 수리 가능 시 기기 수명이 `max(교체주기, 부품공급기간)`으로 자동 연장되는 가정은 인과가 어색합니다. 수리 가능 여부와 목표 사용기간을 별도 입력으로 분리하는 편이 명확합니다.
- 자료: 제조 배출 60 kg, 희소금속 30 g, 배터리 배출 6 kg 등은 출처·범위가 필요합니다.
- 판정: **A — 계산 수정 전 배포 비권장**.

## 권장 처리 순서

1. 08화 시간축 계산을 단일 함수로 재작성하고 결과·타임라인·표가 같은 값을 쓰도록 통합.
2. 06화 공통 난수 시나리오로 비교 조건 통제.
3. 07화 PM10/PM2.5 등급 분리 및 ‘도달률’ 표현을 상대지수로 변경.
4. 01·04·05화에 모형 가정과 한계를 화면에 상시 표시.
5. 각 수치형 모형에 출처·기준 연도·지역 또는 “교육용 가정값” 표기.
6. 수정 후 Chromium 데스크톱(1366×900)·모바일(390×844)에서 실행, 슬라이더 극값, 4회 기록, 검증 탭, 초기화까지 회귀 테스트.
